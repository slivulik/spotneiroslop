# Аудит Sonora (ноябрь 2026)

Живой документ: что найдено, первопричина, статус. Серьёзность: К — критическая, В — высокая,
С — средняя, Н — низкая, Кос — косметическая. Подробности исправлений — в [BUGS.md](BUGS.md).

## Карта системы

- **API** (`services/api`, FastAPI): каталог, стриминг (HLS-плейлисты, подписанные ссылки), авторизация
  (JWT + ротация refresh), админка, события прослушиваний.
- **media-worker** (`services/media-worker`, Dramatiq): проверка, теги, дубли, громкость, кодирование
  лесенки качеств (FLAC hires/lossless, AAC 256/160/96) в HLS fMP4 по 6 с, волна, обложки, превью.
- **Хранилище**: SeaweedFS (S3), бакеты `sonora-media` (приватный), `sonora-public`, `sonora-uploads`.
- **Веб** (`apps/web`, Next.js): плеер = один `<audio>` + hls.js (MSE) или нативный HLS (Safari),
  Web Audio (нормализация, анализатор), очередь и состояние в Zustand (persist), TanStack Query.

## Звук и загрузка (этап 1–2)

| # | Серьёзность | Проблема | Первопричина | Статус |
|---|---|---|---|---|
| A1 | В | Перемотка назад заново качает уже прослушанное | `backBufferLength: 30`; Chrome ограничивает аудиобуфер MSE (~12 МБ); у сегментов каждый раз новая подписанная ссылка + `no-store`, HTTP-кэш бесполезен | Исправлено: сессионный LRU-кэш сегментов (160 МБ), ключ — путь объекта (трек+версия+качество+сегмент). E2E: 0 повторных загрузок |
| A2 | В | Плеер выкачивал весь трек сразу (61 сегмент за 2 с) | hls.js: длина буфера = max(maxBufferLength, maxBufferSize·8/битрейт) — для аудио 60 МБ ≈ 30 мин | Исправлено: буфер только по времени (40 с). Запросов до перемотки 75 → 26 |
| A3 | С | Медленный старт: ~7 последовательных запросов до звука | Каждый сегмент — редирект API → хранилище | Исправлено: плейлист отдаёт прямые подписанные ссылки (3 ч); старт ≈ 240 мс на стенде |
| A4 | С | Каждый трек в «Авто» начинался с низкого качества | hls.js заново оценивал канал | Исправлено: старт с уровня, на котором остановился предыдущий трек |
| A5 | С | «Следующий» грел только ссылку, не данные | prefetch получал лишь `/stream` | Исправлено: заранее кладутся init + 2 сегмента следующего трека |
| A6 | В | Селектор показывал все качества, даже несуществующие | UI брал фиксированный список | Исправлено: только реальные варианты трека (codec, бит, кГц / кбит/с из файла) и только декодируемые браузером |
| A7 | В | «Ошибка декодирования» останавливала музыку | Нет плана Б при отказе декодера | Исправлено: проверка кодека до загрузки, при сбое — продолжение в AAC 256 с той же позиции |
| A8 | С | Две вкладки играли одновременно | Нет координации | Исправлено: BroadcastChannel — новая вкладка ставит остальные на паузу |
| A9 | К | По http сайт не грузил файлы, прослушивания не считались | `crypto.randomUUID` только в защищённом контексте | Исправлено ранее (B-035) |
| A10 | К | Воркер на сервере не запускался | venv собран не по пути запуска | Исправлено ранее (B-034) |

### Проверено (фактические запуски)
