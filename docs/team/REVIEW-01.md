## Найдено, не исправлено (в раунд 2)
**Важные (техревью):**
- I-3 — два параллельных конвейера ранжирования (`recommend.wave` и `wave._pick`), связанные через
  приватные имена. Нужен пакет `services/recs/` с публичным интерфейсом — до работ по «Мэтчу».
- I-4 — таблица `wave_sessions` растёт без ограничений; сайт создаёт сессию на каждое нажатие.
- I-5 — каждый `next` выполняет ~20–40 запросов с полным сканированием каталога под блокировкой.
- I-6 — самодельная блокировка Redis: истекает посреди работы, снимается неатомарно.
- I-7 — при строгих настройках пачка из 1–2 треков и запрос на каждый трек. Попытка дозаполнять
  пачку противоречит закреплённому тестами поведению фильтров; нужно решение по продукту.
- I-9 — запрос текста ждёт два внешних вызова LRCLIB внутри запроса слушателя (до ~16–26 с).
- I-10 — решение админа «убрать текст навсегда» хранится только в Redis.
**Мелкие:** QA API P-2 (плейлист с пустым названием), LY-2 (ключ промаха не сбрасывается при правке
названия), W-3 остаток (нет списка и отмены дизлайков), техревью M-1…M-15.

## Не проверено
Дизайн и анимации (сайт и Android), безопасность целиком, производительность, качество
рекомендаций, Android (сценарии, DTO против OpenAPI, нестабильный тест при первой сборке),
продуктовый вердикт «стало ли свежее и лучше». Импорт из Jamendo вживую (нет ключа), загрузка с
Internet Archive (хосты загрузки недоступны с этой машины).
