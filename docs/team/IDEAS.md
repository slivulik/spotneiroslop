# Sonora — идеи, «Мэтч» и план раундов 2–4

Автор: продуктовый дизайнер команды. Основано на коде `main` (0a051d1) и брифе раунда 1
(Волна 2.0, импорт Jamendo/IA, новый hero, полноэкранный плеер, караоке-тексты).
Ограничения, которые учтены везде: **без новых зависимостей** (только numpy/ffmpeg в воркере,
motion/react на вебе, Compose BOM 2024.12 + Media3 1.5.1 на Android, minSdk 26), один VPS, сервер для друзей.

## 1. «Мэтч» — полная спецификация

### 1.1 Суть
Лента карточек с рекомендованными треками. Каждая карточка — обложка на весь экран и **сразу играющий
клип с хуком (20 с)**. Вправо — «Нравится» (лайк + плейлист «Мэтчи»), влево — «Мимо» (мягкий минус,
это **не** дизлайк навсегда), вверх — «Слушать целиком» (лайк + трек сразу играет в основном плеере).
Колода подстраивается после каждого свайпа: эффект виден уже на 2–3-й карточке.

Принципы: 1) звук сразу, без единого лишнего тапа; 2) обучение видно глазами; 3) ошибку можно отменить;
4) свайп влево никогда не банит артиста скрыто: для бана есть явный пункт в меню «⋯».

### 1.2 Точки входа
- **Android:** 4-я вкладка нижней панели: Главная · Поиск · **Мэтч** · Медиатека. Иконка — две карточки веером.
- **Веб:** пункт в Sidebar под «Главной»; на мобильном вебе вкладка в `MobileTabBar` (там сейчас 3–4 вкладки,
  админская уходит в аватар); на главной рядом с «Моей волной» стоит плитка «Мэтч» (на десктопе
  2 колонки 2:1, на телефоне одна под другой) с мини-веером из трёх обложек следующих карточек.
- Из `/search` (обзор): баннер «Не знаете, что искать? Сыграйте в Мэтч».
- Пустой плейлист и пустые «Любимые треки»: кнопка «Найти через Мэтч».

### 1.3 UX-флоу
1. **Первый вход** (флаг в `settings.match_intro_seen`): одноэкранный интро-оверлей поверх колоды:
   анимированная рука показывает свайп вправо и влево, текст «Вправо — нравится. Влево — мимо. Вверх — слушать целиком».
   Кнопка «Начать» — это и есть пользовательский жест, который снимает запрет браузера на автовоспроизведение.
2. **Холодный старт** (нет истории и лайков): если онбординг не пройден, над колодой лента чипов
   «Что вам ближе?» (жанры, мультивыбор, можно пропустить). Первые 6 карточек — **зондирующие**:
   по одной из 6 разных жанров, популярные (MMR λ=0.5), чтобы учиться быстрее.
3. **Основной цикл:** клип играет → свайп → карточка улетает, следующая (её аудио уже в кэше) за 250 мс
   выходит вперёд и начинает играть с fade-in. Клип доиграл: не переключаем сами (иначе будет ложный
   сигнал), показываем пульсирующую кнопку «▶ Ещё раз» на волне клипа, тихий haptic-тик.
4. **Чекпойнт каждые 20 свайпов:** вместо трека — карточка-итог «6 мэтчей из 20. Сейчас вам заходит:
   инди-рок · ~120 BPM · бодрое» и кнопки «Слушать мэтчи» / «Дальше». Награда и объяснение одновременно.
5. **Выход:** основной плеер был на паузе — остаётся на паузе, мини-плеер виден. Тост
   «Мэтчи сохранены · 6 треков» → ссылка на плейлист.
6. **Гости (v1.1, если `guest_previews` включён):** 10 карточек без входа, потом «Сохраним ваши 4 мэтча —
   зарегистрируйтесь» (лайки держим в localStorage и отправляем после регистрации).

**Веб, десктоп:** колода по центру (карточка 400×620, `aspect 9/14`), фон — размытая обложка текущей
карточки (переиспользовать `.np-backdrop`), между карточками кроссфейд 400 мс. Слева колонка «Ваши мэтчи»:
живой список, новые лайки въезжают сверху (`layout` + spring). Справа панель «Учусь на ходу»: чипы
жанров, артистов и темпа, размер и порядок которых анимированно меняются после каждого свайпа.
Внизу ряд кнопок: `↶ 44` · `✕ 60` · `▶︎ 48` · `♥ 60` (px).
Клавиатура: ← мимо, → нравится, ↑ слушать целиком, Space — пауза клипа, Z / Ctrl+Z — отмена,
Enter — открыть альбом. `Shortcuts.tsx` на `/match` должен отдавать Space и стрелки колоде,
а не основному плееру.

**Веб, мобильный:** колода на `100dvh − шапка − кнопки − tab bar`, панель «Учусь» сжимается
в горизонтальную полосу чипов над колодой.

**Android:** полноэкранная колода с edge-to-edge фоном из палитры, кнопки внизу над bottom bar.
У карточки есть TalkBack custom actions: «Нравится», «Мимо», «Слушать целиком», «Отменить».
Predictive back: при возврате колода уменьшается к 0.92.

### 1.4 Дизайн карточки
- Радиус 28 dp/px, обложка на всю карточку (AVIF/WebP 640, на hi-dpi 1080), снизу градиент из
  `palette.muted_dark` от 0 до 85 %.
- Сверху слева чип причины с иконкой-искрой: «Потому что вы лайкнули Кино», «Новинка недели»,
  «Сюрприз», «Вы слушали это в марте». Сверху справа «⋯» (Не показывать артиста · Открыть альбом · Поделиться).
- Снизу: название (Unbounded 28/32, максимум 2 строки), артист (Onest 17, ссылка), чипы:
  жанр · год · `128 BPM` · `Hi-Res`, если есть.
- **Волна клипа:** 60 столбиков из уже сохранённых 800 peaks, вырезанных по `[hook_start, hook_end]`.
  Прогресс заливает столбики акцентом; тап по волне перематывает клип.
- Штампы при перетаскивании: справа «НРАВИТСЯ» (акцент, −12°), слева «МИМО» (нейтральный, +12°);
  непрозрачность = прогресс жеста.
- Край карточки: при движении вправо светится акцентом (`box-shadow` растёт с прогрессом), при движении
  влево карточка теряет насыщенность (`saturate(1 → 0.55)`).
- Если есть Canvas (раунд 4): вместо обложки беззвучное зацикленное видео.

### 1.5 Жесты, физика, анимации, хаптика

| Параметр | Значение |
|---|---|
| Поворот | `rotate = x / cardW × 14°`; если карточку взяли за нижнюю половину, знак инвертируется (как в Tinder) |
| Порог «вправо/влево» | `|x| > 0.32 × cardW` **или** `|vx| > 800 px/s` (веб) / `1000 dp/s` (Android) |
| Порог «вверх» | `y < −0.22 × cardH` или `vy < −900`; горизонталь при этом < порога |
| Вертикальное сопротивление | вниз elastic 0.15, вверх 0.6 |
| Улёт | spring `stiffness 220, damping 30`, начальная скорость = скорость пальца, цель `±(viewportW + cardW)`, ~280 мс |
| Возврат | spring `stiffness 500, damping 28` (лёгкий overshoot) |
| Следующая карточка | `scale 0.94 → 1`, `y 14 → 0`, тень 0.3 → 1 по прогрессу жеста |
| Кнопки | кнопка нужного направления растёт до 1.15 и заливается по прогрессу |
| Лайк | 8 сердечек-частиц из точки кнопки (spring, 600 мс), счётчик мэтчей в шапке перекатывается как одометр |
| «Слушать целиком» | обложка летит в мини-плеер (общий `layoutId="now-playing-art"` / Compose `sharedElement`) |
| Отмена | карточка возвращается с той стороны, куда улетела, с обратным поворотом, spring 380/26 |
| Reduced motion | без поворота и улёта, кроссфейд 150 мс, всё доступно кнопками |

**Звук в жесте:** громкость клипа падает с прогрессом (на пороге 40 %). При свайпе влево — эффект
«стоп плёнки»: `playbackRate 1 → 0.8` за 180 мс с `preservesPitch=false` (на Android
`PlaybackParameters(speed, pitch)`), потом стоп. При свайпе вправо клип не обрывается, а уходит
в 250 мс fade, пока стартует следующий. Это дёшево и сразу узнаётся.

**Хаптика Android** (через `View.performHapticFeedback`: в Compose BOM 2024.12 нет расширенных
`HapticFeedbackType`). Сделать хелпер `ui/haptics/Haptics.kt` с fallback по API:
- пересечение порога: `GESTURE_THRESHOLD_ACTIVATE` (34+) / `CLOCK_TICK`; возврат за порог: `GESTURE_THRESHOLD_DEACTIVATE` / ничего;
- лайк: `CONFIRM` (30+) / `LONG_PRESS`; мимо: `REJECT` (30+) / `KEYBOARD_TAP`; отмена: `CONTEXT_CLICK`; клип доиграл: `CLOCK_TICK`.

**Веб:** `navigator.vibrate(8)` на пороге и `vibrate([6,40,10])` на лайк, только если API есть
(Android Chrome; на iOS ничего не происходит). Учитывать настройку «Вибрация».

### 1.6 Аудио на клиентах
- **Отдельный плеер клипов**, не основной движок. Веб: `components/match/ClipAudio.ts` с одним
  `HTMLAudioElement` на активную карточку и двумя «тёплыми» (`preload="auto"`) для следующих.
  Громкость = громкость плеера × `10^(gain_db/20)` (не больше 1), чтобы клипы звучали одинаково.
- Вход в «Мэтч»: если основной плеер играет — `player.pause()` и бейдж «Волна на паузе».
- Media Session во время клипа: метаданные карточки, только play/pause (кнопку next на «мимо» **не** мапим).
- **Android:** отдельный `ExoPlayer` в `MatchViewModel` с `AudioAttributes(USAGE_MEDIA)` и
  `handleAudioFocus=true`: основной плеер получает AUDIOFOCUS_LOSS и сам ставит паузу.
  Источник — `CacheDataSource` поверх общего `PlaybackService.cache(...)`; две следующие карточки
  прогреваются через `CacheWriter` в корутине (по ~350 КБ на клип). Ключ кэша `match:{track_id}:{hook_v}`.
- Бюджет: старт звука предзагруженной карточки < 150 мс, первой < 600 мс (p95).

### 1.7 Выбор клипа (хука) в media-worker
Новый модуль `sonora_media/hook.py`, только numpy. Работает на том же PCM, что и `preview.py`
(`decode_mono`, 11 025 Гц).

```
кадр = 0.5 с
rms[t]    — RMS кадра                                   (громкость)
flux[t]   — спектральный поток: STFT 2048/512, Σ max(0, |X_t|−|X_{t−1}|), среднее по кадру (плотность, «drop»)
chroma[t] — 12 бинов высоты тона (FFT-бины 55 Гц–5 кГц → pitch class, log, L2-норма)
rep[t]    — «припевность»: стек chroma за 8 кадров (4 с) → косинусная матрица самоподобия;
            rep[t] = число j с |j−t| > 20 кадров и sim > 0.9·max, нормированное до 0..1
score[t]  = 0.45·z(rms) + 0.25·z(flux) + 0.30·rep        (z — робастный: (x−median)/IQR)
W = 20 с (клип); ищем старт s ∈ [8 %, 80 %] длительности с максимумом mean(score[s:s+W])
```
Уточнения старта (это и делает клип «цепляющим», а не просто громким):
1. **Вход в припев:** ищем самый резкий рост сглаженного RMS в `[s−4 с, s+6 с]`. Если рост > θ (≈ +3 дБ),
   старт = точка роста − 1.5 с, чтобы слушатель услышал подводку и удар.
2. **Привязка к доле:** темп — по автокорреляции огибающей flux (60–180 BPM), фаза — по максимуму
   свёртки с гребёнкой; старт сдвигается к ближайшей доле ≤ старта. Этот BPM записывается в `track_features.bpm`.
3. **Привязка к тексту** (если есть строчный LRC): строки, нормализованный текст которых повторяется ≥2 раз,
   считаются припевом. Если начало такой строки попадает в `[старт−3 с, старт+5 с]`, старт = `line.start − 0.3 с`.
   Это самый точный дешёвый детектор припева.
4. Фейды: вход 0.15 с (сейчас `FADE_S=1.0` съедает сильную долю), выход 1.2 с.

Запись: `track_features.hook_start_ms`, `hook_end_ms`, `analyzer_version="hook-1"`.
`preview.m4a` перерендеривается от `hook_start` (30 с: гости слушают весь, «Мэтч» — первые
`clip_ms`, по умолчанию 20 с), так что `preview_start_ms == hook_start_ms`.

Заодно в той же стадии (`ANALYSIS`, после `LOUDNESS`) пишем остальные признаки, тоже на numpy:
`bpm`; `key`/`mode` (корреляция средней chroma с профилями Крумханзля); `energy` (сигмоида от
LUFS + среднего flux, 0..1); `acousticness` ≈ 1 − нормированный спектральный центроид и flux;
`danceability` ≈ сила пика автокорреляции на темпе. Valence честно не считаем (null).
Маппинг для фильтра настроения Волны 2.0: бодрое = energy>0.65 и bpm>110; спокойное = energy<0.4;
весёлое = мажор и energy>0.5; грустное = минор и energy<0.5.

**Backfill:** `sonora-media backfill-analysis [--only-missing] [--limit N]` в существующем `backfill.py`
берёт лучший сохранённый файл (lossless → high) из S3, считает признаки и хук, перерендеривает превью.
Порядок — по `play_count desc`, чтобы популярное было готово первым. ~2–3 с CPU на трек.
Пока backfill не дошёл до трека, есть быстрый фолбэк в API: хук = окно с максимальным средним по 800 peaks
волны с привязкой к повторяющимся строкам текста. Клип в этом случае играет из старого `preview.m4a`
со смещения внутри файла.

### 1.8 Как свайпы учат рекомендации
**В сессии (реальное время).** Состояние сессии в Redis `match:{sid}` (TTL 6 ч):
- пул кандидатов (≤600 id), собранный при старте из `recommend.taste()` + co-listening + жанры
  соседей + новое/популярное, с кэшированными признаками (artists, genres, bpm, energy, year, static_score);
- веса сессии `w_artist`, `w_genre`; центроиды `liked_c` и `passed_c` в пространстве (bpm/200, energy, acousticness, year_norm);
- журнал свайпов с дельтами (нужен для отмены).

Обновление на каждом свайпе:

| Действие | w_artist | w_genre | Центроид |
|---|---|---|---|
| ♥ нравится | +1.0 | +0.6 | `liked_c` EMA α=0.3 |
| ▶︎ целиком | +1.5 | +0.9 | `liked_c` EMA α=0.4 |
| ✕ мимо, dwell < 3 с | −1.0 | −0.5 | `passed_c` EMA α=0.3 |
| ✕ мимо, 3–12 с | −0.5 | −0.25 | α=0.2 |
| ✕ мимо, > 12 с | −0.2 | −0.1 | α=0.1 |

Все веса сессии умножаются на 0.92 после каждого свайпа: свежие реакции важнее.
Скор кандидата:
`0.35·static + 0.25·Σw_genre + 0.20·max w_artist + 0.15·cos(f, liked_c) − 0.15·cos(f, passed_c) + novelty + gumbel(τ)`,
τ = 0.6 на первых 10 карточках, дальше 0.25. Следующие 3 карточки отбираются через MMR (λ=0.7) ради разнообразия.
Слоты исследования: 70 % — лучший скор, 20 % — «соседний» жанр (по co-listening), 10 % — «Сюрприз»
(помечается чипом). Пересчёт 600 кандидатов в Python занимает доли миллисекунды и делается прямо в ответе на свайп.

**Почему обучение видно:** у клиента всегда 3 карточки (верхняя, следующая с прогретым звуком,
третья — только картинка). Ответ на свайп N возвращает новую 3-ю карточку, посчитанную **уже с учётом
свайпа N**.

**Надолго:**
- ♥ и ▶︎ → `LikeTrack` (идемпотентно) + генерируемый плейлист «Мэтчи» (`type=generated`, новый
  `generated_kind='match'`, новые сверху). В медиатеке есть «Сохранить как мой плейлист» (копия).
- Все свайпы → таблица `match_swipes`. `recommend.taste()`: «мимо» снижает вес артиста на −0.4 × затухание
  (полураспад 30 дней); 2 «мимо» подряд по артисту = мягкий бан в «Мэтче» на 30 дней.
- Волна 2.0 исключает треки, получившие «мимо» за последние 30 дней. Настоящий `Dislike` — только из меню «⋯».

### 1.9 Анти-повторы
1. Никогда не показывать: треки из медиатеки (лайкнутые), с `Dislike`, уже лайкнутые в «Мэтче»;
   «мимо» — не раньше чем через 90 дней.
2. Не показывать треки, засчитанные как прослушанные за последние 30 дней («Мэтч» — для открытий).
3. Не больше 1 трека артиста на 8 карточек и 2 треков одного релиза за сессию; не больше 3 подряд
   одного основного жанра, если последние 3 не лайкнуты.
4. 3 «мимо» подряд по жанру → жанр выключен до конца сессии.
5. Допуск: `status=ready`, `playable` (explicit-фильтр), длительность ≥ 60 с, есть `preview_key`.
6. Пул кончился → ослабляем п. 2 до «забытого» (слушали > 90 дней назад, не лайкали, чип «Вы слушали это
   в марте») → потом экран «всё пролистано».

### 1.10 Отмена
- Стек из 5 последних свайпов, кнопка ↶ (неактивна при пустом стеке) и Z / Ctrl+Z.
- Сервер вычитает сохранённые дельты; если лайк был создан этим свайпом (`created_like=true`),
  удаляет `LikeTrack` и строку из «Мэтчей». Возвращает карточку со свежим URL клипа и новую 3-ю
  карточку (старая, посчитанная с ошибочным свайпом, выбрасывается).
- Если отменили «▶︎ целиком», основной плеер ставится на паузу и возвращается к прошлому треку.

### 1.11 Пустые и ошибочные состояния
| Состояние | Что показываем |
|---|---|
| Гость (флаг превью выключен) | 3 размытые карточки веером, «Войдите, чтобы находить музыку свайпами», кнопка входа |
| В каталоге < 20 подходящих треков | «Пока мало музыки для Мэтча» + админу ссылка «Загрузить» / «Импорт открытой музыки» |
| Всё пролистано | итог сессии (мэтчи / свайпы, топ-жанр) + «Слушать мэтчи» · «Показать знакомое» · «Моя волна» |
| Нет сети | карточка-скелет с shimmer, «Нет соединения», «Повторить»; свайпы на Android копятся в Room-очереди |
| Клип не загрузился | карточка играет беззвучно с бейджем «Без превью», автопропуск через 1.5 с, **не** считаем свайпом, `POST …/swipes` с `action="unavailable"` |
| Автовоспроизведение заблокировано (веб) | на карточке большая кнопка ▶ «Нажмите, чтобы слушать» |

### 1.12 Контракт API (набросок; имена Pydantic → имена TS-схем)
```
MatchClip      { url: str (подписанный, 1 ч), offset_ms: int (смещение в файле превью),
                 duration_ms: int 10000..30000, track_offset_ms: int (позиция в полном треке),
                 waveform: int[60] (0..255), gain_db: float|null }
MatchReason    { kind: "liked_artist"|"similar_track"|"genre"|"new"|"popular"|"friends"|"surprise"|"forgotten",
                 text: str (готовая русская строка), ref_id: uuid|null }
MatchFeatures  { bpm: int|null, key_label: str|null ("ля минор"), energy: float|null }
MatchCard      { card_id: uuid, track: TrackOut, clip: MatchClip, reason: MatchReason, features: MatchFeatures }
MatchStats     { swipes: int, likes: int, streak: int, playlist_id: uuid|null }
MatchCheckpoint{ likes: int, swipes: int, genres: GenreRef[], bpm: int|null, mood: "energetic"|"happy"|"calm"|"sad"|null }

MatchStartIn   { genre_ids: uuid[] (≤5) = [], include_known: bool = false, clip_ms: int 10000..30000 = 20000, limit: int 1..5 = 3 }
MatchSessionOut{ session_id: uuid, cards: MatchCard[], stats: MatchStats }
MatchSwipeIn   { swipe_id: uuid (клиентский, идемпотентность), card_id: uuid, track_id: uuid,
                 action: "like"|"pass"|"play"|"unavailable", dwell_ms: int>=0, clip_played_ms: int>=0, want: int 0..3 = 1 }
MatchSwipeOut  { next: MatchCard[], stats: MatchStats, checkpoint: MatchCheckpoint|null }
MatchUndoOut   { restored: MatchCard, next: MatchCard[], stats: MatchStats }

POST   /v1/me/match/sessions                          MatchStartIn  -> 201 MatchSessionOut
GET    /v1/me/match/sessions/{sid}/cards?limit=1..5   -> 200 MatchCard[]      (восстановление после перезагрузки)
POST   /v1/me/match/sessions/{sid}/swipes             MatchSwipeIn  -> 200 MatchSwipeOut
DELETE /v1/me/match/sessions/{sid}/swipes/{swipe_id}  -> 200 MatchUndoOut   (только 5 последних, иначе 409)
GET    /v1/me/match/likes?cursor=&limit=              -> 200 Page[MatchLikeOut{ track: TrackOut, liked_at }]
GET    /v1/admin/match/metrics?days=14                -> 200 MatchMetricsOut   (для «Обзора» в админке)
```
- Чужая или неизвестная сессия → 404 в общем формате ошибок. Повтор `swipe_id` → тот же ответ (200).
- Ссылка клипа подписывается так же, как сегменты HLS, и **не зависит** от `guest_previews`.
- Rate limit GCRA: 4 свайпа/с на пользователя.
- Клипы **не** отправляются в `/v1/events/batch`. «▶︎ целиком» запускает обычное воспроизведение с
  `context_type="match"` (добавить в Literal вместе с `wave`, `mix`, `radio`).

### 1.13 Данные
Миграция `0008_match`:
`match_swipes(id uuid pk = swipe_id, user_id fk, session_id uuid, track_id fk, action varchar(12), dwell_ms int,
clip_played_ms int, reason_kind varchar(16), created_like bool, undone_at timestamptz null, created_at)`,

### 1.14 Метрики (Postgres → карточка в админском «Обзоре»)
| Метрика | Цель v1 |
|---|---|
| Доля лайков (♥+▶︎ / все свайпы) | 25–40 % (меньше 15 % — плохие рекомендации, больше 60 % — слишком безопасные) |
| **Кривая обучения:** доля лайков на карточках 31–40 против 1–10 | рост ≥ +8 п.п. |
| **D7-повтор:** лайкнутое в «Мэтче» и потом прослушанное целиком в течение 7 дней | ≥ 35 % |
| Свайпов за сессию (медиана) / сессий ≥ 20 свайпов | ≥ 25 / ≥ 40 % |
| Время до первого лайка | < 60 с |
| Доля «мимо» с dwell < 2 с | < 30 % (иначе клип выбран плохо) |
| Доля отмен | < 5 % (больше — неочевидные жесты) |
| Разнообразие: разных артистов на 20 карточек | ≥ 16 |
| Задержка старта звука p95 (прогретая / первая) | < 150 мс / < 600 мс |

**1. Анализатор аудио.** *Что:* стадия `ANALYSIS` в воркере (см. §1.7) + backfill.
*Почему это любят:* сам по себе пользователю не виден, но благодаря ему работают настроения Волны,
чипы «128 BPM», daylist и переходы между треками. *Бэкенд:* worker + миграция 0009; API отдаёт
`features` в «Мэтче» и в «О треке». *Клиенты:* строка «128 BPM · ля минор · энергия 0.8» в панели «О треке».

**2. Онбординг «Выбор вкуса».** *Что:* после регистрации (и пункт «Обновить вкус» в настройках) —
экран пузырей: жанры, потом артисты выбранных жанров. Пузыри физические и расталкивают друг друга;
выбранный растёт ×1.35 с акцентной обводкой и подтягивает похожих артистов. Кнопка «Готово» появляется
после 3 выборов. *Почему:* новый друг сразу получает свою волну, а не «популярное». *Бэкенд:* уже есть
`POST /v1/me/onboarding`; добавить `GET /v1/onboarding/artists?genre_ids=` (топ-артисты жанров) и
учёт `onboarding` в `taste()` (×4 жанру, ×5 артисту — как подписка). *Веб:* `/onboarding`, Verlet-раскладка
на `requestAnimationFrame` без библиотек, редирект после регистрации. *Android:* `Canvas` + собственная
мини-симуляция, haptic `CLOCK_TICK` на выбор.

**3. Микро-анимации и хаптика.** *Что:* единые токены движения уже есть (`tokens.motion.spring`) —
добавить: морфинг play↔pause (SVG path / `AnimatedVectorDrawable`), сердечко лайка с частицами,
одометр у чисел (лайки, минуты), кроссфейд скелетон → контент вместо резкой подмены, «дышащий»
эквалайзер текущей строки от реального анализатора (веб: `engine` уже создаёт `AnalyserNode`),
pull-to-refresh на Android с волной. Хаптика по всему Android (`Haptics.kt`): лайк, долгое нажатие,
шаги ползунка громкости и EQ (`SEGMENT_TICK`/`CLOCK_TICK`), щелчок при перемотке через границу
строки текста. *Почему:* дорогое ощущение без новых экранов.

**4. «Итоги года».** *Что:* 8–10 полноэкранных сторис (тап вправо/влево, удержание = пауза,
прогресс-полоски сверху): минуты за год (одометр), топ-трек (он играет фоном), топ-5 артистов,
жанровая эволюция по месяцам, «часы слушания» (радиальный график по часам), первый трек года,
самый длинный день, «тип слушателя» («Ночной исследователь», «Верный фанат» — по правилам), сравнение
с друзьями («Вы и Бодя сошлись на 3 артистах» — только с согласия), финальная карточка со «Скачать
картинку». Плюс плейлист «Ваш 2026». *Почему:* самый шерящийся формат в индустрии, а у нас ноябрь.
*Бэкенд:* `GET /v1/me/replay/{year}` (из `ListeningHistory`, кэш в Redis на сутки), generated
playlist `kind='replay'`. *Веб:* `/replay/2026`, картинки 1080×1920 через существующий
`app/og/[kind]/[id]` (`next/og`). *Android:* `HorizontalPager` + `graphicsLayer`, шеринг PNG через
`FileProvider`. В админке — тумблер «Итоги доступны с…».

**5. Совместные плейлисты.** *Что:* «Пригласить» (ссылка или выбор друга), аватарки соавторов у
плейлиста, у каждого трека мелко «добавил Денис». *Почему:* сервер для друзей — это его суть.
*Бэкенд:* таблица уже есть; эндпоинты `POST/DELETE /v1/me/playlists/{id}/collaborators`, токен
приглашения, права в `add/remove/order`; `PlaylistTrack.added_by` уже есть — отдать его в API.

**6. Друзья.** *Что:* подписка на людей (взаимная = «друзья»), страница профиля `/u/{id}`
(публичные плейлисты, топ-артисты месяца), справа на десктопе панель «Сейчас слушают» (трек, живой
эквалайзер, «5 мин назад»; тап — играть тот же трек), на Android — блок на главной.
Приватность: «Показывать друзьям, что я слушаю» (по умолчанию вкл.) и «Приватная сессия» на 6 ч.
*Бэкенд:* `user_follows`, presence в Redis (пишем из `/events/batch`, TTL 10 мин),
`GET /v1/me/friends/activity`; SSE — позже, сейчас хватит polling раз в 30 с.

**7. Бленд.** *Что:* выбираешь друга и получаешь «Совпадение вкусов 72 %» (анимированный круг)
и общий плейлист на 50 треков, который обновляется каждый день: поровну любимого у обоих плюс общее.
*Бэкенд:* сходство = косинус векторов `taste()` (артисты + жанры), generated playlist на пару
пользователей. *Почему:* повод для разговора, «смотри, мы на 72 %».

**8. Кроссфейд, gapless и «Умные переходы».** *Что:* кроссфейд 0–12 с; gapless для альбомов
(без кроссфейда внутри одного релиза, если треки идут подряд); режим «Умные переходы» (как AutoMix
в Apple Music): переход начинается на сильной доле, длительность — 8 или 16 тактов по BPM, хвост
с тишиной (по waveform) обрезается. *Веб:* второй `HTMLAudioElement` + второй `MediaElementSource`
в том же `AudioContext`, кривые equal-power; `engine.ts` уже умеет предзагружать сегменты следующего
трека. *Android:* в Media3 1.5 кроссфейда нет — две инстанции ExoPlayer в `PlaybackService` с
переключением `MediaSession.setPlayer` или `ForwardingPlayer`; gapless — штатный для элементов одного
плейлиста. *Бэкенд:* `features.bpm`, `hook`, `outro_silence_ms` из анализатора.

**9. Очередь 2.0.** Разделы «Сейчас», «Далее в очереди» (добавлено вручную), «Далее из: Моя волна»;
перетаскивание (`Reorder` на вебе, `LazyColumn` + drag на Android), свайп для удаления с отменой,
«Очистить очередь». Тост «Будет следующим · Отменить» после «Играть следующим».

**10. «Радио от трека» и «Похожие».** Пункт «Радио по треку» в меню трека и на странице трека
(Волна 2.0 уже принимает `seed_track`), полка «Похожие треки» в панели «О треке». Только клиенты.

**11. «Ваш месяц».** 1-го числа — generated playlist «Ваш октябрь» из топ-30 месяца + уведомление
на главной. Архив прошлых месяцев в медиатеке. Почти бесплатно поверх `/me/stats`.

**12. Плейлист дня.** *Что:* одна плитка на главной, название меняется по времени суток и вкусу:
«Бодрое утро вторника: инди и 120 BPM», «Поздний вечер: эмбиент и ля минор». Обновление каждые
4 часа, 40 треков, кнопка «Сохранить версию». *Бэкенд:* история по корзинам (день недели ×
6 слотов) → топ-жанры и настроения слота (из анализатора) → сборка плейлиста через `wave` с фильтрами;
названия — из шаблонов-словарей (прилагательное настроения + жанр + время), без LLM.

**13. Smart Shuffle.** Третье состояние кнопки перемешивания (иконка с искрой): после каждых
3 треков плейлиста вставляется рекомендация, помеченная искрой; ♥ — оставить в плейлисте, ✕ — убрать.
Бэкенд: `GET /v1/me/playlists/{id}/smart-shuffle?limit=` (Волна с seed = треки плейлиста).

**14. Поиск 2.0.** Карточка «Лучший результат» (крупно, с кнопкой ▶), поиск по тексту песен (ILIKE
по `lyrics` → раздел «В тексте песни» с подсвеченной строкой), транслитерация (`kino` → «Кино», `ыгкф`
→ `sura` — раскладка), «Возможно, вы искали», в недавних — сущности с обложками (в `search_history`
уже есть `entity_type/entity_id`), голосовой ввод на Android (`RecognizerIntent`, без зависимостей).

**15. Карточки для сторис.** «Поделиться» → выбор вида: обложка на градиенте палитры / строчка текста
(долгое нажатие на строку в тексте → выделение 1–4 строк → карточка) / «Сейчас слушаю». PNG 1080×1920
через `next/og`; на Android — нативный share sheet с картинкой. Ссылка ведёт на страницу трека
с 30-секундным превью для гостей.

**16. Офлайн на Android.** «Скачать» для альбома, плейлиста, «Любимых», «Мэтчей»; Media3
`DownloadManager` + `DownloadService` (они уже в `media3-exoplayer`), шифрованный кэш, лимит устройств
(фаза 3 roadmap), раздел «Скачанное», «Только Wi-Fi», индикатор-кольцо на обложках. Денис и друзья
ездят по Европе — для них это функция номер один на телефоне.

**17. Jam.** Хост создаёт сессию → QR или ссылка → друзья добавляют треки в общую очередь со
своих устройств; играет только у хоста (как Spotify Jam). Позже — синхронное воспроизведение на всех
устройствах по серверным часам. *Бэкенд:* SSE `GET /v1/jams/{id}/events` + Redis pub/sub, REST для
действий.

**18. «Новинки подписок».** Колокольчик в шапке с точкой: новые релизы артистов, на которых
подписан; приглашения в плейлисты; «Бодя лайкнул ваш плейлист». На Android — системные уведомления
через WorkManager-poll раз в 6 ч (FCM — фаза 8).

**19. Android-обвязка.** Glance-виджет 4×1 и 2×2 (обложка, play/next, ♥), плитка Quick Settings
«Моя волна», «встряхни телефон — другая волна» (как в Яндекс Музыке; `SensorManager`, выключаемо),
app shortcuts на долгое нажатие иконки: «Моя волна», «Мэтч», «Поиск».

**20. Canvas.** Таблица `canvas` уже есть: загрузка 3–8 с вертикального mp4 в админке → транскод
в воркере (720p, без звука, H.264) → фон полноэкранного плеера и карточки «Мэтча».

**21. «Ваш звук».** Страница вкуса: карта жанров (пузыри по доле), «вы слушаете быстрее 70 %
пользователей» (BPM), утренний или ночной слушатель, тональности. Переиспользуется в «Итогах года».

**22. «Здоровье каталога».** Админка: сколько треков без текста, обложки, хука или признаков, с битым
превью; кнопки «Запустить backfill»; массовые действия в «Треках» (выделить → опубликовать / жанр /
настроение / удалить); пагинация.

## 3. Чек-лист полировки по экранам

Пометка ⚠ — исправить в раунде 2; «(р1)» — проверить после мерджа раунда 1, экран переделывается.

### Главная
- ⚠ Пустое состояние «Загрузите релизы в панели управления» видят **все**. Для обычных пользователей:
  «Здесь скоро будет музыка», для админа — кнопка «Загрузить» и «Импорт открытой музыки».
- ⚠ Градиент WaveCard захардкожен (`#3b2a9a`, `#1b1340` на вебе, `0xFF2A1A6E` на Android) и ломает
  свой или динамический акцент и светлую тему → `color-mix(in oklch, var(--accent) …)` / `lerp` от `C.accent`. (р1)
- ⚠ `MixCover`: при 1–3 обложках в сетке 2×2 дыры. Нужна раскладка: 1 → на всю, 2 → пополам,
  3 → большая + 2 маленьких.
- Скелетон (`h-56`) не совпадает с hero (`aspect-[16/6]`) → при загрузке прыгает раскладка. Повторить реальные пропорции.
- Приветствие 44 px + «Продолжить слушать» + Волна занимают первый экран целиком; на десктопе
  поставить Волну и «Мэтч» в одну строку 2:1.
- Секции появляются без ритма: дать общий `Reveal` со stagger 40 мс только при первом показе.

### Поиск
- Нет карточки «Лучший результат» → крупная плитка слева, треки справа (как у Spotify).
- Нативный `<select>` сортировки выбивается из стиля liquid glass → сегментированный контрол или меню-поповер.
- Заголовок `«{q}»` в `display-l` на длинных запросах переносится в 3 строки → `line-clamp-1` + `title-1`.
- Вкладки с нулём результатов просто тускнеют (opacity .35) → скрывать.
- В истории только текст, хотя в API есть сущности → показывать обложки и тип.
- Ничего не нашлось: добавить «Возможно, вы искали…» и кнопку «Найти через Мэтч».

### Альбом
- ⚠ **Баг:** `TrackList` вызывает `start()` и в `onClick`, и в `onDoubleClick` → play/pause/play на
  двойной клик. Решение: на десктопе одиночный клик выделяет строку, двойной — играет (Spotify);
  на тач-устройствах (`pointerType`) играет одиночный тап.
- ⚠ `Tilt` игнорирует `max` и ничего не наклоняет (заглушка `lift`) → либо настоящий наклон только для
  `(hover:hover) and (pointer:fine)`, либо убрать проп.
- Нет полок «Ещё у {артиста}» и «Похожие релизы» внизу; нет кредитов (`TrackCredit` есть в БД).
- Строки треков: нет ♥ на тач-устройствах, пока трек не лайкнут (только hover) → на мобильном
  показывать «⋯», а ♥ убрать в меню.
- Футер: ℗ и дата — мелким серым; добавить «Hi-Res 24/96» с объяснением в тултипе.

### Артист
- ⚠ Ссылка автора фото всегда подписана «Фото: Wikimedia Commons», даже если фото загрузил админ →
  показывать, только если `photo_credit` указывает на Commons.
- ⚠ «0 слушателей за месяц» на маленьком сервере звучит грустно → при < 3 скрывать или писать «Новый артист на Sonora».
- Подписка — это сердечко; у Spotify и Яндекса это текстовая кнопка «Подписаться» / «Вы подписаны»
  с анимированной галочкой. Понятнее.
- «Популярные треки» — сразу 10 → 5 + «Показать ещё».
- На ≤ 375 px ряд из 5 кнопок переносится → ▶ и «Подписаться» видны, остальное убрать в «⋯».
- ⚠ Пользовательские страницы импортируют `toast` из `components/admin/ui` (4 файла: `AppShell`, `TrackMenu`, страницы артиста и плейлиста) → вынести в
  `components/ui/toast.tsx`, чтобы админский модуль не попадал в пользовательские бандлы.

### Плейлист
- Режим «Порядок» — отдельное состояние → владельцу дать перетаскивать прямо в списке за ручку,
  без отдельного режима.
- Под своим плейлистом — полка «Рекомендуемые треки» с кнопкой «+» (Smart Shuffle-логика, раунд 4)
  и «Найти через Мэтч».
- Пустой плейлист: добавить встроенный поиск прямо в пустом состоянии.
- Для generated-плейлистов («Мэтчи», «Ваш месяц») — своя обложка-обозначение и «Сохранить как мой».

### Плеер (док, полноэкранный, мини) (р1)
- Док: `QualitySelect` скрыт до 1440 px, а ошибка воспроизведения — обрезанная красная строка →
  ошибка тостом с «Повторить», качество — бейджем у названия, клик по нему открывает выбор.
- Мини-плеер на мобильном вебе: свайп влево/вправо = следующий/предыдущий (обложка едет за пальцем),
  свайп вверх = открыть. Прогресс 2 px → 3 px с закруглением.
- Полноэкранный на мобильном: 3 круглые кнопки панелей + «Играет из» в одной строке тесно →
  панели переносятся вниз, под транспорт (как у Apple Music).
- **Android:** свайп по обложке не двигает её → `Animatable` offset + подглядывание соседних обложек
  (карусель как в Яндекс Музыке), haptic на пороге, spring-возврат.
- Android: нет «Добавить в плейлист» и «Радио» в полноэкранном плеере → меню «⋯» в шапке.
- Пауза: обложка уменьшается до 0.9/0.92 — хорошо; добавить затемнение фона на 8 %.

### Текст песни (р1)
- Когда текста нет, показывать «Найти текст» (Волна 2.0 / on-demand LRCLIB) с индикатором, а не тупик.
- Подпись источника «Текст: LRCLIB» мелко внизу (атрибуция).
- Долгое нажатие на строку → выделение → «Поделиться строчкой» (идея 15).
- Перемотка тапом по строке: подсветить строку-цель на 300 мс до прыжка (сейчас прыжок без обратной связи).

### Медиатека
- Нет сортировки (недавние / по алфавиту / по артисту), фильтра-поиска внутри, переключателя сетка/список.
- История: сгруппировать по «Сегодня / Вчера / 12 ноября», сейчас сплошная лента.
- Закрепление (pin) до 4 элементов сверху; «Мэтчи» и (Android) «Скачанное» — закреплённые системные.
- Пустые состояния хорошие («Нажмите на сердечко…») — добавить иллюстрацию-волну и CTA «Мэтч».

### Настройки
- Нативный `<select>` качества → сегментированный контрол с подписями «~1.3 МБ/мин».
- На десктопе липкое оглавление разделов слева; на мобильном — якоря.
- Новые пункты по раундам: Вибрация (2), длина клипа «Мэтча» 15/20/30 с (2), кроссфейд /
  gapless / «Умные переходы» (3), приватность для друзей и «Приватная сессия» (3), «Обновить вкус» (2).
- Android: настройки доступны только через аватар на главной → продублировать в «Медиатеке» (шестерёнка).

### Админка
- ⚠ `window.confirm` (замена обложки/фото/текста) → стеклянный диалог подтверждения с превью
  «было → станет».
- Нет массовых действий и пагинации в «Треки/Релизы/Пользователи» → чекбоксы + панель действий
  внизу, infinite scroll.
- «Обзор»: добавить карточки «Мэтч» (метрики §1.14) и «Здоровье каталога» (идея 22).
- Загрузка: после публикации — кнопка «Открыть релиз на сайте».

### Общее (оба клиента)
- Android: переходы навигации — shared-axis X для перехода вглубь (альбом, артист), fade-through для
  вкладок; predictive back для полноэкранного плеера.

- Скелетоны: единый shimmer с правильными пропорциями, кроссфейд 180 мс в контент.
- Фокус-кольца на всех кастомных контролах (сегменты, чипы, карточки «Мэтча») — проверить Tab-обходом.

## 5. Исследование (коротко)
- Discz — свайп-открытия с клипами по **15 с**, лайки сразу уходят в плейлист: этот формат доказан.
  [Rolling Stone](https://www.rollingstone.com/music/music-features/discz-tiktok-recommendation-app-1324785/)
- Spotify daylist: учитывает, что слушают в определённое время дня и дни недели, часто обновляется
  в течение дня и каждый раз получает новое игривое название; текущую версию можно сохранить.
  [Engadget](https://www.engadget.com/spotifys-latest-playlist-auto-adapts-to-your-day-122541712.html)
- Яндекс «Моя волна»: контекст (время, день, устройство), встряхивание телефона для смены подборки,
  «ИИ-реплики» с фактами об артистах. [3DNews](https://3dnews.ru/1141969/v-yandeks-muzike-radikalno-obnovilas-moya-volna/print)
- Apple Music AutoMix: time-stretch и beat matching, анализ тональности и темпа для момента перехода.
  [MacRumors](https://www.macrumors.com/2025/06/12/ios-26-automix-apple-music/)
  Наша версия без time-stretch: переход на сильной доле, длина по тактам.
