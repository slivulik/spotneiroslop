# Roadmap

Исходный промт пришёл обрезанным на разделе 5.3, поэтому раздел 19 (фазы) неизвестен. Ниже —
рабочий план, построенный по разделам 0–5.2; его нужно сверить с оригиналом, когда придёт
остаток промта.

## Фаза 1 — фундамент ✅

* Монорепо (pnpm workspaces + uv), CI, Makefile, `.env.example`.
* `packages/design-tokens`: JSON → CSS, Tailwind v4, TS, Kotlin; проверка контраста.
* `infra`: docker-compose (Postgres+pgvector, Redis, S3, ClickHouse, Meilisearch, API),
  схема событий ClickHouse с материализованными представлениями, Caddy.
* `services/api`: полная схема данных (34 таблицы, миграция 0001), auth (e-mail+пароль,
  Google, refresh-ротация с детектом повторов, подтверждение e-mail, сброс пароля), `/me`,
  устройства, настройки (JSON Merge Patch), онбординг, чтение каталога (треки, батч, релизы,
  артисты, топ-треки, релизы артиста, жанры, настроения), ETag, rate limit, единый формат ошибок.
* `packages/api-schema`: OpenAPI 3.1 + TS-клиент с авто-refresh.

## Фаза 2 — media-worker и админ-API загрузки ✅

* `/v1/admin/uploads` (подписанные PUT прямо в S3 вместо tus — проще и не грузит API),
  статус и логи задачи, перезапуск с любого этапа, публикация релиза.
* `services/media-worker`: шаги 5.1 №1–7 и 9–12 (кроме ML-анализа, см. ниже), запись в каталог,
  album gain, чекпоинты этапов.
* `tools/uploader-cli`, команды `sonora-api create-admin` / `init-storage`.
* Хранилище: SeaweedFS вместо MinIO (образы MinIO больше не публикуются).

## Ускоренный срез: сайт, на котором можно слушать ✅

По просьбе — раньше фаз 3–4 целиком:
* API: `/v1/tracks/{id}/stream` (HLS, ротация подписей сегментов), `/v1/tracks/{id}/preview`,
  `/v1/releases` (новые релизы).
* `apps/web`: вход/регистрация, главная, альбом, артист, плеер (мини и полноэкранный),
  выбор качества, нормализация, Media Session, горячие клавиши, мобильная вёрстка.
* Деплой: сервис `web`, Caddy как единая точка входа.

Из фазы 3 ещё не сделано: лайки/подписки/дизлайки, плейлисты, офлайн-загрузки, `/events/batch`,
история прослушиваний, тексты и Canvas в API. Из фазы 4: поиск, PWA/Service Worker, кроссфейд и
gapless на двух элементах, эквалайзер, пословные тексты, WebGL-визуал волны.

## Управление сайтом и редизайн ✅

По просьбе — раньше фаз 3–6:
* Админка `/admin`: обзор, стриминг в реальном времени и рубильники сервиса, загрузка из браузера,
  треки/релизы/артисты с текстами (LRC), плейлисты редакции, жанры, конструктор главной из блоков,
  пользователи (роли, блокировка, выход везде, удаление).
* API: `/v1/home` из блоков, плейлисты редакции, жанры, тексты, `/v1/events/batch`, история,
  `/v1/search` (пока ILIKE по каталогу; Meilisearch — фаза 5).
* Сайт: liquid glass, живой фон под обложку и в такт, подсветка краёв под курсором, синхронные
  тексты, страницы плейлиста/жанра/поиска.

Дальше по просьбам: пользовательские плейлисты и шаринг, лайки и библиотека, рекомендации и
«Моя волна», Android.

## Фаза 3 — стриминг и библиотека

`/tracks/{id}/stream|preview|download` с подписанными URL и бесшовным обновлением,
лимит офлайн-устройств; лайки/дизлайки/подписки, плейлисты (CRUD, reorder дробными индексами,
соавторы), `/me/library/*`, офлайн-синхронизация `/me/library/sync` с Idempotency-Key,
`/events/batch` → ClickHouse, история прослушиваний, тексты и Canvas.

## Фаза 4 — веб-клиент (PWA)

Next.js 15 + React 19: корневой плеер (hls.js/нативный HLS, Web Audio: кроссфейд, нормализация,
EQ, анализатор), state machine плеера, Media Session, горячие клавиши, Service Worker,
главная/поиск/библиотека/артист/альбом/плейлист, полноэкранный плеер с Canvas и пословными
текстами, WebGL-визуал волны.

## Фаза 5 — поиск

Meilisearch: индексация, опечатки, транслитерация, синонимы, поиск по текстам, suggest,
история поиска.

## Фаза 6 — рекомендации и «Моя волна»

`services/recs`: аудио-эмбеддинги, коллаборативные векторы, гибрид, сессионный вектор в Redis,
`/wave/sessions`, похожие треки, миксы, «Открытия недели», «Радар», A/B-эксперименты,
`/home` из серверных секций.

## Фаза 7 — Android

Kotlin 2 + Compose + Media3 (MediaLibraryService, свой AudioProcessor для EQ, SimpleCache,
DownloadManager с шифрованием), модули по разделу 2, Kotlin-клиент из OpenAPI, виджеты Glance,
AGSL-визуал волны, baseline profiles.

## Фаза 8 — синхронизация устройств, push, шеринг, админка UI

SSE/WebSocket-синхронизация плеера, FCM, `/share/*` с OG и story.png, `apps/admin`.

## Фаза 9 — оптимизация и нагрузка

`EXPLAIN ANALYZE` главных эндпоинтов, k6 (`tools/loadtest`), бэкапы, Grafana/Prometheus.

## Осознанно отложено из фазы 2

* **Шаг 8 (ML-анализ: Essentia BPM/тональность/настроения, Whisper язык вокала, аудио-эмбеддинги)**
  → фаза 6: модели и их версии выбираются вместе с рекомендательной системой.
* **Шаг 13 (индексация в поиске)** → фаза 5 вместе с Meilisearch.
* Gapless для MP3-источника в HLS: задержка/padding из LAME-заголовка сохранены в `track_files`,
  но `elst` в fMP4 для MP3 не переписывается (поведение декодеров MP3-в-MP4 различается);
  проверить на клиентах в фазах 4/7. Для AAC обрезка в начале проверена, хвост (padding, ~5 мс)
  ffmpeg на фрагментированных потоках не срезает — клиенты используют `encoder_padding`.
* Формат текстов — временный документ v1 (`{"version":1,"type":"line"|"static",...}`) до
  спецификации `packages/lyrics-core` (раздел 6 промта не получен). Пословные тексты (TTML) — там же.
* Редактирование метаданных и UI админки (`apps/admin`) — фаза 8; сейчас — API.

## Осознанно отложено из фазы 1

* `GET /artists/{id}/related` — требует эмбеддингов/коллаборативных данных (фаза 6).
* Письма отправляются через `BackgroundTasks`; перевод на Dramatiq с ретраями — в фазе 2,
  вместе с воркером.
* Локализация писем (сейчас русский) — вместе с i18n веб-клиента.
* Kotlin-клиент из OpenAPI — в фазе 7 (нужен Android SDK).
* Таблица `idempotency_keys` создана; middleware Idempotency-Key — в фазе 3.
